# 研究方法（Research Methods）

本文件提供各任务模式共用的具体研究方法，按需加载，不要求每次任务全部使用。

## 1. 文献精读

阅读或摘录学术文献时保留：

- 研究对象、研究设计（RCT/队列/体外/仿真等）、样本量、比较基线
- 主要/次要终点、定量结果（效应量、置信区间，如有）
- 局限（单中心、小样本、厂商资助、随访时长）
- 原文定位（页码/图表号）；未取得全文时明确写「摘要依据」

未取得全文不编造上述字段。

## 2. 参数比较口径统一

建立竞品/技术矩阵**之前**先统一：

- 型号与版本（第几代？固件版本？）
- 单位与量纲
- 测试条件（离体/在体、环境温湿度、操作者）
- 地区与价格口径（出厂/经销/终端；含税与否；年份）

无法统一的维度注明「不可比」，不做强行排序；缺失值标「未查得」。

## 3. 前沿研究信号

发现早期技术信号时记录：技术机制、研究对象/设计、样本、比较基线、终点、结果、局限、**研究阶段**（仿真/体外/动物/人体可行性/临床）、同行评审状态、转化缺口（距商业应用还缺哪些环节：安全性、量产、法规、临床证据、成本）。

输出「技术信号表 + 相对现有方案的变化 + 转化缺口 + 下一步验证建议」。不将动物阳性结果外推人体有效，不将专利公开当成产品已实现。

## 4. 需求研究

### 4.1 角色分离

区分：**使用者 / 购买者 / 付费者 / 决策者**（必要时加维护者）。不同角色的问题、权重和证言价值不同，分开记录。

### 4.2 需求假设格式

需求一律先写为可检验假设，字段：需求ID、角色/场景/任务、需求描述、现有替代、问题频率、影响（可量化更好）、证据ID、验证状态。模板见 `templates/requirements-traceability.md`。

### 4.3 一手研究边界

- 只有二手资料（评论、报道、论坛）时：**只输出验证方案，不生成访谈结果和付费意愿结论**。
- 验证方案要素：非诱导式访谈提纲/观察方案/试用设计、样本选择依据、偏差来源、通过条件（建议值标注「建议」）、反证标准。
- 付费意愿（WTP）必须有实测数据（调查或实验）才能下结论。

## 5. 二手研究边界

公开资料能回答：市场规模、竞品参数、技术路线、法规、财务基准。
公开资料不能回答：你的真实客户是否买单、内部能力是否匹配、真实成交价格。
后者进入「待验证事项」，交给一手研究。

## 6. 持续调研与复盘

更新既有研究时：

1. 以上次报告为基线，逐条比对：新增 / 修订 / 撤回 / 仍未知。
2. 优先复核时效性高或影响大的信息（价格、法规、证照、财务）。
3. 标注受影响的声明、需求、假设和决策；未变化章节不重写。
4. 说明原建议是否改变、改变依据、下一次复审触发条件。
