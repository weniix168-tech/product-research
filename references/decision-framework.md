# 决策框架（Decision Framework）

本文件支撑 SKILL.md 第 4 节模块 4（法规）、8（专利）、11（方案）、12（财务）与第 5 节决策产出。按需加载。

## 1. 决策五态

建议必须落入五态之一：**继续 / 附条件继续 / 暂缓 / 终止 / 证据不足**。

每次建议同时给出：

- 下一阶段验证任务（做什么）
- 投入上限（花多少算停）
- 必要证据（凭什么继续）
- 通过/停止条件（量化或明确的判断标准）
- 建议责任角色与复审时间

用户未确认的门槛、负责人、预算一律标记「建议」，不声称已批准。

## 2. 阶段验证计划（Stage-Gate 轻量版）

| 要素 | 要求 |
| --- | --- |
| 阶段 | 概念验证 / 技术验证 / 商业验证 等，按任务命名 |
| 关键假设 | 该阶段要检验的最关键假设（1–3 条） |
| 最小验证/交付物 | 通过该阶段所需的最小实验、原型或证据 |
| 通过/停止条件 | 明确、可判断；建议值标注「建议」 |
| 投入上限 | 该阶段最大投入 |
| 评审角色 | 谁评审；未确认时标注建议 |

模板见 `templates/validation-gate-plan.md`。

## 3. 轻量 PIC（产品创新章程）

立项模式下用一页写清：

- **背景**：为什么现在做（机会与问题）
- **聚焦范围**：目标客户、关键场景、核心技术范围
- **目标与成功指标**：业务目标 + 可衡量的成功指标
- **边界（不做什么）**：明确排除的范围，防止范围蔓延
- **资源条件与约束**：已知约束；未知标注待确认

## 4. 项目组合与优先级

多项目竞争资源时使用：

1. **先列硬约束**：法规禁止、资源上限、时间死线、战略边界——硬约束直接过滤。
2. **再选评价维度与权重**：如战略匹配、市场吸引力、技术可行性、风险；权重标注「建议值」或「已确认」并列依据。
3. **分析依赖、资源冲突与机会成本**：做 A 就挤占 B 的什么资源。
4. **给排序 + 敏感性说明**：结果对哪个假设最敏感。
5. 证据不足时给**分组**（如「优先验证组」「观察组」）或补证优先级，**不制造精确排名**。

## 5. 财务分析口径

- 每个输入标注状态：**已知 / 估计 / 假设**，并给出来源或估算依据。
- 统一币种、税费、预测期与销量口径。
- **利润 ≠ 现金流**：回收期与盈亏平衡按现金流口径计算。
- 常用口径：研发投入、持续运营费用、收入、自由现金流、盈亏平衡点、回收期。
- 必须做**情景**（乐观/基准/悲观）与**敏感性**（对哪些输入最敏感）。
- 缺关键输入（价格、销量、报价）时：**提供公式和数据获取方法**，不编造精确预测把模型填满。
- 公式与口径要写出来，便于复核。

## 6. 法规核查要点

- 顺序：先确认**用途、产品边界、目标市场和时间**，再查分类、路径、标准。
- 区分标准的：发布 / 实施 / 过渡期 / 替代版本 / 目标市场采用状态。**最新发布不自动等于唯一适用版本**。
- 记录：主管机构、文件编号、版本、适用条件、核对日期。
- 不把某类产品的要求泛化给所有产品（如别用诊断设备的要求推治疗设备）。
- 输出「法规要求 → 设计输入草案」的映射，供后续开发使用。

## 7. 专利与 FTO 初筛

- 分别记录：申请/公开号、类型（发明/实用新型/外观设计）、司法辖区、法律状态、相关同族、检索日期。
- **统计口径先定义**：按申请件数还是按同族数；**PCT 是申请途径，不与国家或专利类型相加**；地域标识遵循数据库实际口径。
- 输出：相关权利要求 → 技术要素映射；有效性/地域/时间问题清单；待专业复核项。
- **FTO 初筛 ≠ 法律意见**：未检出不等于可自由实施，不代替特定产品、市场与日期下的律师判断。初筛只产出「线索 + 待复核问题」。
